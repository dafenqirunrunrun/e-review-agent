# v1.6.1 真实评论文本标注规范

## 目标

本规范用于真实电商评论文本的风险治理标注。标注结果仅用于外部评估、路由校准和后续 SFT 准入审计；外部测试集不得参与索引、Prompt 选择、融合权重选择或阈值校准。

## 字段

| 字段 | 说明 |
| --- | --- |
| `risk_type` | `after_sales_risk`、`negative_review`、`normal_review` |
| `risk_level` | `low`、`medium`、`high` |
| `need_human_review` | 是否必须人工复核 |
| `evidence_spans` | 当前评论文本中的最小证据片段 |
| `expected_action` | 建议运营动作，不包含自动退款、赔付、封禁 |
| `ambiguity_flag` | 文本证据不足、表达矛盾或多风险并存时为 true |
| `annotator_confidence` | 0 到 1，低于 0.7 必须写入备注 |

## 标注规则

1. 只根据当前评论文本和允许的商品类目、评分标注，不使用模型输出、检索结果或历史案例。
2. `evidence_spans` 必须能在原文中逐字找到；不能把推理结论写成证据。
3. 售后、食品安全、电池安全、假货质疑、退款/退货争议、虚假发货等高风险或责任边界不清的样本应转人工。
4. 主观不喜欢、口味偏好、颜色偏好一般标为 `negative_review`/`medium` 或更低，不得升级为高风险，除非存在明确质量/安全证据。
5. 信息不足时优先标记 `ambiguity_flag=true`，并将 `need_human_review` 置为 true 或给出补充信息动作。
6. 不允许根据商品品牌、价格或历史案例推测当前评论没有描述的事实。
7. 所有用户名、用户 ID、店铺 ID、手机号、地址、订单号和快递单号必须在标注前脱敏。

## 双人标注与一致性

- 至少 100 条文本样本需要双人标注。
- 一致性指标优先使用 Cohen's Kappa；多标注人时可使用 Krippendorff's Alpha。
- 无第二标注人时必须在报告中写明限制，不得伪造一致性。

## 拆分隔离

1. dev/适配集可用于错误分析、阈值校准和报告示例。
2. external test 只用于最终评估，不允许参与 Prompt、RAG 权重、路由阈值或 SFT 数据选择。
3. 同一用户、商品或模板家族不得跨 dev/test。
